# 1C Sell Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The cashier's core sell loop on `pos-web` (which Electron wraps) running against the offline-first `@retailos/sync` device store, with every order attributed to the PIN'd staff (1F). Screens per the approved POS-03/04/05/06/07/08/13/14 mockups.

**Kickoff decisions (roadmap `05-roadmap/phase-1-core-pos-mvp.md` §1C, user-approved 2026-07-12):**

1. Browser store is real — Sell flow runs against the `@retailos/sync` `SqlDriver` port; pos-web gets a **wa-sqlite/OPFS** driver (degrades to in-memory when OPFS unavailable). Electron keeps `better-sqlite3`.
2. Full receipt loop — POS-05 email (Mailpit dev adapter) + QR to admin **`/r/<order-ulid>`** built end-to-end. ESC/POS stays Electron-only (browser = native print dialog), verified interactively.
3. Refund facts land now — `refund.completed` outbox fact + server ingest + restock projection. Exchange = Phase 2.
4. Owner PIN escalation gates Phase-1 role ceilings (discount >10%, refunds, voids, tax-exempt, no-sale) — reuses 1F `PinPad` + `verifyPin`. Full permission editor + audit UI = Phase 2.
5. Parked carts are device-local (`parked_carts` SQLite table), not synced.

## Global Constraints

- TypeScript strict; no `any` without `// why:` comment.
- Money = integer minor units. Cart math lives ONLY in `@retailos/domain` (`calculateCart`) — identical offline + on server revalidation (AD-2).
- Every business row carries `store_id`; server reads/writes go through `db.tenants.forStore(storeId).tx(...)`.
- Wire format snake_case; ids are Crockford ULID `/^[0-9A-HJKMNP-TV-Z]{26}$/` (no I, L, O, U).
- Device SQLite is the single source of truth for the UI — the UI never awaits the network. Sync happens in the background.
- Run repo-wide gate before claiming done: `pnpm turbo typecheck lint test` (pnpm at `~/.local/bin`).
- Commit convention: `type(scope): summary (1C)` + `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.

## Architecture notes

- **Driver port:** `@retailos/sync` already defines `SqlDriver` + a `better-sqlite3` adapter. Add a `wa-sqlite/OPFS` adapter (browser) and an `in-memory` adapter (dev fallback + tests). The shared React Sell app depends only on `SqlDriver`/`SyncClient`, never on a concrete driver.
- **Device reads:** the Sell screen reads catalog (`products`/`variants`/`barcodes`/`inventory_levels`/`categories`/`tax_rates`) and history (`orders`/`order_lines`/`payments`) from the local mirror bootstrapped by 1B. New read helpers live in `@retailos/sync` (`queries.ts`).
- **Writes:** completed sale → existing `recordSale` outbox fact. Refund → new `recordRefund` outbox fact. Parked cart → local-only `parked_carts` table (no outbox).
- **Escalation:** `verifyPin` (1F) against an Owner in the local `staff` mirror; a small `useEscalation` hook wraps the PinPad modal and returns the approving staff id for audit fields on the fact.
- **Receipts:** admin Next.js serves public `GET /r/<order-ulid>` (read-only, no auth, tenant via order ulid → store). Email send = new API endpoint behind a mailer adapter (Mailpit SMTP in dev). QR encodes the `/r/<ulid>` URL.

## Acceptance (subset of Phase-1 demo script this workstream must satisfy)

- Sell: scan/tap items, apply line + cart discount, park, retrieve, cash + change, split tender, receipt with tax breakdown (email + QR).
- Refund one line of a prior order to cash, restock toggled; Owner PIN gates it.
- Orders list shows the day; order detail timeline correct.
- All writes survive a reload (OPFS) and appear in admin exactly once after sync.
